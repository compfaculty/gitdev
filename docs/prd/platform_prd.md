# Secure Red/Blue Development Platform — Product Requirements Document

**Version:** 1.0  
**Status:** Approved for implementation  
**Residency:** EU infrastructure preferred (Hetzner-first)  
**Ops model:** Self-hosted core

---

## 1. Executive Summary

This platform delivers a reproducible **Infrastructure as a Service** boundary for red-team and blue-team engineering: self-hosted GitLab, isolated CI runners, private VPN access, hardware-backed identity, and signed code trust — with explicit controls for abuse, takeover, supply chain, and DDoS/developer continuity scenarios.

---

## 2. Objectives

| ID | Objective |
|----|-----------|
| O1 | Single controlled SCM + CI + registry boundary with RBAC and audit trails |
| O2 | VPN-only administrative and developer access paths (WireGuard via Tailscale/Headscale pattern) |
| O3 | Ephemeral runners in dedicated network namespaces with default-deny egress |
| O4 | Fire-and-forget deploy via Terraform (compute/network) + Ansible (hardening, GitLab, runners) |
| O5 | Resilience under abuse: minimal public surface, rate limits, documented fallback access |

---

## 3. Non-Goals (Phase 1)

- Multi-region active/active
- Internet-exposed GitLab UI/API or shared public runners
- Ukraine-only DC mandate (defer until provider modules stabilize; abstract for swap)

---

## 4. Functional Requirements

| ID | Requirement |
|----|-------------|
| F1 | Self-hosted GitLab (Omnibus or Helm — Ansible supports Omnibus MVP) |
| F2 | Private container registry bundled with GitLab |
| F3 | Group/project RBAC; no anonymous read on production groups |
| F4 | GitLab Runner registration via tokens from CI variables / vault pattern |
| F5 | Terraform provisions Hetzner cloud network, servers, firewalls |

---

## 5. Security Requirements

| ID | Requirement |
|----|-------------|
| S1 | SSH from internet denied; bastion reachable only via VPN-aligned firewall rules |
| S2 | MFA + hardware tokens for privileged GitLab/OIDC identities (policy + IdP responsibility) |
| S3 | Signed commits/tags enforced on protected branches (see `platform/policies/`) |
| S4 | CI secrets short-lived where possible; no long-lived PATs in job logs |
| S5 | DDoS-aware design: GitLab origin private; public edge only for explicitly approved services behind WAF/CDN pattern |
| S6 | `nftables` baseline: connection caps and rate limiting on edge-facing hosts |

---

## 6. Reliability & DR

| Metric | Target (Phase 1) |
|--------|------------------|
| RPO | ≤ 15 minutes (GitLab backup cadence configurable) |
| RTO | ≤ 4 hours |
| Backup | Daily snapshots + encrypted off-Object-Storage copy documented in DR runbook |

- [ ] `terraform apply` in `infra/terraform/environments/prod` yields network + bastion + placeholder GitLab/runner IPs (after `terraform.tfvars` filled).

# Threat Model (STRIDE-aligned)

## Assets

- Source code, CI pipelines, container images, signing keys, VPN control plane, Terraform state, backup buckets.

## Adversaries (lab-authorized framing)

- **A1:** Credential phishing / token theft against developers or CI.
- **A2:** Malicious merge request / pipeline injection.
- **A3:** Runner breakout + lateral movement.
- **A4:** DDoS against VPN edge or residual public endpoints affecting productivity.
- **A5:** Supply chain: poisoned dependencies or compromised base images.

## Trust Boundaries

1. **Internet → Edge:** Deny-all default; allow only hardened reverse proxy endpoints if explicitly deployed.
2. **VPN fabric → Management subnet:** Bastion, GitLab SSH over internal paths.
3. **GitLab → Runners:** Job tokens scoped; runners in isolated VLAN (`ci_subnet`).
4. **Runners → Internet:** Default deny; allowlist mirrors only.

## Mitigations (mapping)

| Threat | Mitigations |
|--------|-------------|
| Stolen PAT/CI_JOB_TOKEN | Scoped tokens, short TTL, OIDC-for-Terraform pattern (future), branch protection |
| Malicious MR | CODEOWNERS, mandatory review, signed commits, pipeline rules |
| Runner breakout | NetworkPolicy-equivalent via Hetzner private network + nftables egress allowlist Ansible role |
| DDoS | Private GitLab, optional CDN in front of non-critical public assets, nftables caps, failover VPN path (runbook) |
| Supply chain | Pinned CI images, internal mirror playbook hooks, SBOM policy (staging) |

## Risk Register (initial)

| Risk | Likelihood | Impact | Treatment |
|------|------------|--------|-----------|
| State file exposure | Medium | Critical | Remote backend + encryption; least-privilege IAM on bucket |
| IdP misconfiguration lockout | Low | High | Break-glass procedure in `docs/howto/auth_security_setup.md` |
| Single-region outage | Medium | High | Offsite backups + DR runbook |
